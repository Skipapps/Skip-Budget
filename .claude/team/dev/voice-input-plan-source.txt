Voice Input for Skip
How to add voice logging for receipts, bills, subscriptions and salary — free, with no
third-party APIs and no AI parsing.
Requirements
# Requirement How this plan meets it
1 No use of AI All parsing (amount, type, merchant, date) is plain rules and lookup tables
you write. Speech-to-text uses the phone’s own built-in engine (see note
below).
2 Free, no 3rd-party API Apple and Google speech engines ship with the phone. Every library is open
source and runs on the device. No keys, no per-use cost, no server.
3 Works with confusing
speech
Multiple guesses, self-correction handling, fuzzy matching, a confidence
score, follow-up questions and a confirmation sheet — nothing saves wrong
without the user seeing it.
One honest note. Turning speech into text always needs a trained model — there is no
rule-based way to do it. The phone already has one: Apple’s speech recognition on iPhone and
Google’s on Android. It is free, it is not a third-party API, and it can run fully on the device.
Everything after the speech becomes text is plain rules with no AI.

Part 1 — Speech to text (the phone does it)
• Use the expo-speech-recognition package. It wraps the iOS and Android speech engines.
• It does not run in Expo Go. You need a development build: npx expo run:ios /
run:android, or EAS Build.
• Set requiresOnDeviceRecognition: true so audio never leaves the phone — works offline
and is better for privacy in a finance app.
• Set maxAlternatives: 3 to get the engine’s top 3 guesses. This is key for messy speech.
• Pass contextualStrings — words you expect (Netflix, rent, salary, electric bill, plus the
user’s own merchants) so the engine favors them.
ExpoSpeechRecognitionModule.start({
lang: 'en-US',
interimResults: true, // live transcript on the sheet
maxAlternatives: 3,
requiresOnDeviceRecognition: true,
contextualStrings: ['Netflix', 'Spotify', 'rent', 'salary',
'electric bill', ...userMerchants],
});

Handling confusing speech
No system is right 100% of the time. The real goal is to never save something wrong
without asking. Five things together get you there:
1. Parse all 3 guesses and keep the best
Score each guess: +40 if it found an amount, +25 for a type, +20 for a merchant, +15 for a
date. If guess #1 says “forty fife” but guess #2 says “forty five”, guess #2 wins.
2. Let the score decide what happens next
Score What the user sees
High (75+) Confirmation sheet with everything filled in — one tap saves
Medium (40–74) Sheet with what was found; empty fields highlighted
Low / no amount One short follow-up question, e.g. “How much was it?”, then listen again for just
that answer
3. Always show the confirmation sheet
Every field (type, amount, merchant, date) is editable. Nothing saves without a tap.

4. Learn from corrections
When the user fixes “Spot a fly” to “Spotify”, save that pair in Supabase or local storage. Next
time it matches exactly. This is a simple lookup table, not AI.
5. Never dead-end
If nothing is understood, open the normal manual form with whatever was caught already filled
in — no error screen.
The parser, in shape
A sketch of the main function. Each helper is a small, testable rule.
function parseVoice(alternatives: string[], userAliases: Record<string, string>) {
const results = alternatives.map(raw => {
let t = cleanFillers(raw.toLowerCase());
t = applyCorrections(t); t = applyAliases(t, userAliases); // keep text after "no wait" / "actually"
// "spot a fly" -> "spotify"
t = wordsToNumbers(t);
const amount = extractAmount(t);
const type = detectType(t);
const merchant = fuzzyMerchant(t);
const date = chrono.parseDate(t) ?? new Date();
const frequency = detectFrequency(t);
const score = (amount ? 40 : 0) + (type ? 25 : 0)
+ (merchant ? 20 : 0) + (date ? 15 : 0);
return { amount, type: type ?? 'receipt', merchant, date, frequency, score, raw };
});
return results.sort((a, b) => b.score - a.score)[0];
}
