# Add flows — stepped amount-first entry

Date: 2026-09-12 · Author: Priya (Product Design lead) · Build: Pia + Paulo
Extends `design-direction-2026-09-11.md`. Where the two disagree, the direction doc wins on tokens,
radii, spacing and accessibility; this doc wins on the shape of the add flows.

## Hard constraint — read before writing a line

**Presentation and screen flow only.** Nothing under `src/api`, `src/lib` (hooks, queries, mutations,
`format`, `date`, `split`), `src/stores`, `supabase/` or `ios/` changes. No mutation is renamed, no
argument is added or removed, no saved record changes shape.

An add flow may be **split into steps**, but at the end it calls **the same mutation with the same
fields and the same values** as it does today. If a step split would require a new field, a defaulted
field, or a dropped field — do not split it, come back to me. Every field captured on a screen today
is still captured after this refresh. Money is never rounded, pre-filled, defaulted to a guess, or
re-derived; the amount that leaves the keypad is the string the screen already holds in state.

Two more things that are not in scope and must not drift in: `src/lib/haptics.ts` (use the exported
`tap()`; see §1.5), and `src/lib/date.ts` (`MONTHS_SHORT`, `WEEKDAY_INITIALS`, `getDaysInMonth`,
`getFirstWeekday`, `parseClock`, `toClockValue`, `formatClock`, `formatFullDate`, `toIsoDate` are all
already there and are all we need).

Verified against https://docs.expo.dev/versions/v57.0.0/ — this spec adds **no new native module**.
It is React Native core + NativeWind + `lucide-react-native` + `expo-haptics` (already installed,
already wrapped) + `react-native-reanimated` for the two optional transitions in §1.4.

## 1. The StepFlow shell

New presentational component: `src/components/flow/step-flow.tsx`. It owns chrome only. It holds no
form state, knows no mutation, and takes the current step as a prop.

    <StepFlow
      title="Add an expense"
      steps={3}
      current={0}            // zero-based
      onBack={...}           // step 0 → router.back(); otherwise → previous step
      primaryLabel="Continue"
      primaryDisabled={!valid}
      onPrimary={...}
      footerSlot={...}       // optional: the Delete action when editing
    >
      {step content}
    </StepFlow>

### 1.1 Anatomy, top to bottom

| Element | Spec |
|---|---|
| Back | 44×44 `Pressable`, `ChevronLeft` 24, `strokeWidth={2}`, `colors.ink`, `rounded-full`, `active:bg-ink/5`, absolutely positioned left in the header row so the title stays optically centred |
| Title | centred, `font-poppins-semibold text-[17px] text-ink`, `numberOfLines={1}`, `maxFontSizeMultiplier={1.3}` |
| Step indicator | `mt-4`, a centred row, `gap-2` (see §1.2) |
| Content | `flex-1`, screen gutter `px-6` from `Screen`, `mt-8` under the indicator |
| Primary | full-width `Button` pinned to the bottom, `mb-2` above the safe-area inset |

The shell renders inside the existing `<Screen>` (`showBack={false}` — StepFlow draws its own back)
so the gutter, `RefreshControl` colour and safe-area handling stay in one place. Keyboard steps pass
`avoidKeyboard`, exactly as the screens do today.

### 1.2 Step indicator

A row of `steps` marks. Current step: **40×10, `rounded-full`, `bg-ink`** (dark mode: the ink ramp is
already light on dark, so this is the screenshot's light pill with no special-casing). Other steps:
**10×10, `rounded-full`, `bg-ink/20`**. Completed and upcoming look the same — the pill alone says
where you are; two different inactive treatments is a code nobody reads.

Not pressable. Wrapped in one `View` with `accessibilityRole="progressbar"`,
`accessibilityLabel="Step 2 of 3"`, `accessibilityValue={{ min: 1, max: steps, now: current + 1 }}`.
The individual marks are `accessibilityElementsHidden`.

### 1.3 Back behaviour

- Step 0 → `router.back()`. Nothing is saved, nothing is asked.
- Step > 0 → previous step. Everything typed stays; steps are **views over one piece of form state**
  held by the screen, never remounted, never reset.
- Hardware/gesture back does the same: `StepFlow` takes `onBack` and the screen wires the same
  handler to a `BackHandler`-less approach — on iOS the gesture is the header back, which is ours.
- Editing an existing record opens on **step 1 (Details)**, not step 0, for the same reason
  `add-bill.tsx` already opens on `details` when editing: making someone re-type an amount they came
  to change is busywork. The amount step is one tap away via the indicator's own back.

### 1.4 Transitions

Optional and last: `react-native-reanimated` `FadeIn`/`FadeOut` (120ms) on the content container,
`Layout` on the indicator pill. If it costs a frame on a real device, drop it — the flow is correct
without it. No slide, no shared element, no gesture-driven paging.

### 1.5 Haptics

Every key press, every chip, every day cell, every Continue: `tap()` from `@/lib/haptics` (the
existing `expo-haptics` `impactAsync(Light)` wrapper, iOS-only, respects the preference switch).
`success()` on a completed save. `warn()` when Continue is pressed while invalid — but Continue is
disabled while invalid, so in practice `warn()` fires only on a save error.

> SDK 57 also exposes `Haptics.selectionAsync()`, which is the idiomatic keypad tick. Adding a
> `selection()` export to `src/lib/haptics.ts` is one line — but `src/lib` is outside this spec's
> scope, so **do not add it**. Founder/CEO call; open question 4.

### 1.6 Primary button

The existing `Button` (`variant="primary"`, already `rounded-full`, already `min-h-16`). Full width,
one per step.

| Step | Label |
|---|---|
| Any step but the last | `Continue` |
| Last step, creating | `Save expense` / `Save bill` / `Save subscription` / `Save receipt` / `Save card` / `Save account` / `Create group` |
| Last step, editing | `Save changes` |
| Last step, in flight | `Saving…`, disabled (this is exactly what the screens do today) |

Disabled = the existing `opacity-50` plus `accessibilityState={{ disabled: true }}`. **Disabled is
never the only feedback**: when a step is invalid, the reason is on screen next to the field it
belongs to (§5.2), not hidden behind a dead button.

### 2.2 The question line

`mt-10`, `font-poppins text-[20px] text-ink/60` — use `text-muted`, left-aligned to the gutter (the

### 2.3 The figure

A baseline-aligned `flex-row`:

- Prefix `$`: `font-poppins-bold text-[28px]`, `mt-3` to sit on the big figure's baseline,
  `text-muted` while empty, `text-body` once typed. `allowFontScaling={false}`.
- Figure: `font-poppins-bold text-[64px]`, `text-muted` while the draft is empty or zero, `text-ink`
  once typed. `allowFontScaling={false}`, `numberOfLines={1}`, `adjustsFontSizeToFit`,
  `minimumFontScale={0.6}` so `999,999,999.99` still fits a 375pt screen.
- Grouping while typing: reuse `displayAmount()` from `amount-pad.tsx` verbatim (thousands separators
  on the whole part, fraction untouched, a trailing `.` preserved so `12.` renders as `12.`).
- The figure is **not** `formatCurrency`'d while typing — `formatCurrency` is for committed money;
  a live `$0.00` under a finger that has typed `0` is a lie about state. On leaving the step the raw
  string goes into the same `amount` state the screen holds today, unchanged.
- `percent` variant: no `$` prefix, a trailing `%` at the same 28px, same rules. Used by
  `loan-calculator.tsx` only, which already passes `unit="percent"` to `AmountPad`.

### 2.4 The keypad

Twelve tiles, 3 columns: `1 2 3 / 4 5 6 / 7 8 9 / . 0 ⌫`.

| Property | Value |
|---|---|
| Tile | `flex-1`, `h-[64px]` (≥44pt, comfortable at 4 rows), `rounded-[16px]` |
| Fill | `bg-ink/5` — the tonal surface, **no border, no shadow** |
| Pressed | `active:bg-ink/10` |
| Gaps | `gap-3` between columns, `gap-3` between rows (12pt, matches the capture's proportions) |
| Digit | `font-poppins text-[26px] text-ink`, `allowFontScaling={false}` |
| Backspace | `Delete` from lucide, size 24, `strokeWidth={1.8}`, `colors.ink` |
| Container | `px-6` (the screen gutter), `mt-auto` so the pad sits low and the figure floats |

Key rules — **these are the current `amount-pad.tsx` rules and they do not change**, they only move:

1. `.` — ignored if the draft already contains one; on an empty draft it yields `0.`.
2. Digits after `.` — capped at **2**. A third is ignored (no buzz, no error: it is a miss, not a
   mistake).
3. Leading zero — typing a digit while the draft is exactly `0` replaces it.
4. `⌫` — removes one character, including the `.`. On an empty draft it does nothing.
5. **Max whole digits: 9** (`999,999,999`). A tenth digit is ignored. This is new and it is a
   presentation guard only: it stops the figure shrinking to unreadable, and it is above any figure
   a person will type into a budgeting app. It must never silently *truncate* an existing value —
   a value loaded from an existing record is displayed in full whatever its length, and the cap
   applies only to appended keystrokes.
6. Long-press `⌫`: **not in this pass.** One-character delete only. (Open question 5.)

Each key: `accessibilityRole="button"`, `accessibilityLabel` = the digit, `"Decimal point"`,
`"Delete last digit"`. `tap()` on press.

### 2.5 Validity

`Continue` is enabled when `Number(draft) > 0`, **except** on the flows where the amount is optional
today (`add-card` balance, `add-account` balance) — there it is always enabled and a `0` amount is a
legitimate answer. See the per-flow table (§6) for which is which. No flow gains a requirement it
does not have today, and none loses one.

### 2.6 What happens to `amount-pad.tsx`

It stays. Three screens use it for a *secondary* amount that is not the flow's headline figure
(an exact share in `add-expense`, the expected-income figure in `add-account`, the rate in
`loan-calculator`), and a modal is right there. Restyle its internals to match this step — tonal
`bg-ink/5` tiles at `rounded-[16px]` with no border, 26px digits, the 64px figure, `tap()` per key,
and the footer `Button` relabelled **`Done`** (unchanged) — and extract the shared bits so the step
and the modal cannot drift:

    src/components/flow/amount-keypad.tsx   — the 12 tiles + the press rules (used by both)
    src/components/flow/amount-figure.tsx   — the prefix + figure + displayAmount (used by both)

`AmountPad`'s public props (`title`, `caption`, `value`, `unit`, `onCancel`, `onConfirm`) do not
change, so its six call sites compile untouched.

## 3. Step 2 — Details

One screen's worth of fields, scrollable, gutter `px-6`, `gap-6` between fields (direction doc §1).
Nothing here is new information; it is the same fields the screen collects today, re-grouped.

### 3.1 Controls

| Today | Step 2 |
|---|---|
| `SegmentedControl` (account type, split mode, subscription cycle, subscription active) — its only three importers | **`ChoiceChips`** — pill row, wraps. `SegmentedControl` is retired app-wide; see the pills sweep. |
| `ChoiceChips` (recurrence, pay frequency, reminder, insights range) | unchanged in behaviour, restyled to the pill anatomy |
| `SelectField` (amount, dates, payer) | **pill variant**: `rounded-full`, `min-h-14`, `px-5`, `bg-ink/5`, no border, trailing 20px glyph in `colors.muted` |
| `TextField` | **unchanged.** A text input is not a pill (pills sweep §4). |
| `SourceTiles` ("Paid with") | unchanged component, flattened per the direction doc |
| `ColorPicker`, `IconPicker`, `GroupIconPicker`, `BrandField` | unchanged |
| `Switch` (simplify debts) | unchanged — a two-state system control, not a chooser |

`SelectField` grows one prop: `variant?: 'field' | 'pill'` (default `'field'`, so nothing outside
these flows moves). The label stays a `FieldLabel` above it in both variants.

### 3.2 Field order per flow

Ordered by what a person can answer without thinking, which is what the screens already imply.

- **add-expense** — What for (`TextField`) · Paid by (pill `SelectField` → the existing inline member
  list) · Split (`ChoiceChips`: *Equally* / *Exact amounts*) · Between / Who owes what (the existing
  checkbox rows; in *exact* mode each row's share opens `AmountPad`) · the live remainder line,
  verbatim: `$4.20 left to assign.` / `$4.20 over the total.` / `The shares add up.`
- **add-bill** — Company (`BrandField`) · Name (`TextField`) · Icon (`IconPicker`, still only when
  category is `other` and no brand is chosen) · Category (`ChoiceChips`) · Paid with (`SourceTiles`) ·
  Note (`TextField`, optional) · the loan `ScheduleCard` when present, unchanged.
- **add-subscription** — Service (`BrandField`) · Paid with (`SourceTiles`) · Note · Active
  (`ChoiceChips`: *Active* / *Cancelled*, replacing the `SegmentedControl`).
- **add-receipt** — Store (`BrandField`) · Paid with (`SourceTiles`) · Note. The Scan / Upload pair
  moves to **step 1**, above the question line, as two `ActionPill`s — scanning fills the amount, the
  store and the date at once, so it belongs before the amount, not after it.
- **add-card** — the live `PaymentCard` preview at the top (it is what makes the colour choice sighted,
  and it now updates from the amount typed on step 1 as well) · Network (`NetworkPicker`, **unchanged** —
  the networks are chosen by their logos, and a pill fill would cover the logo) · Name of the card ·
  Colour (`ColorPicker`) · Last 4 digits. The `CollapsibleSection` "More setup" wrapper goes: with the
  amount on step 1 and the due date + reminder on step 3, there is nothing left to collapse.
- **add-account** — Bank name · Account type (`ChoiceChips`) · Name of the account · Colour ·
  Last 4 digits · Expected income (pill `SelectField` → `AmountPad`) · Pay frequency (`ChoiceChips`).
- **add-group** — Group name · Icon (`GroupIconPicker`) · the carried-names note, unchanged.

| add-account | a bank name |

## 5. States

### 5.1 Loading an existing record (edit)

The screen already waits on its query before mounting the form (`add-bill` returns a `BillForm` keyed
on the record; `add-subscription` and `add-receipt` seed from `initial`). Keep that. While the query
is pending, render the **StepFlow shell with skeletons**, not a bare page: title in place, indicator
in place, a `Skeleton` block where the figure goes and one per field. Primary button disabled,
label `Continue`. Never render a `$0` figure for a record that is still loading — that is a false
money figure on screen, and it is the one mistake in this whole spec I will not accept.

### 5.2 Validation

Inline, under the field it belongs to, `font-poppins text-[13px] text-danger`,
`maxFontSizeMultiplier={1.4}`. Never a toast, never an alert. The existing copy is already good and
is kept **verbatim** — it is the product's voice and it is not mine to re-write mid-flight:

    add-expense    "What was it for?" · "Enter how much it came to." ·
                   "Pick at least one person to split it between." · "Say who paid." ·
                   "$4.20 is still unassigned." · "The shares come to $4.20 more than the total."
    add-bill       "Give the bill a name." · "Enter how much it costs." ·
                   "Pick the date it starts." / "Pick the first due date."
    add-subscription "Pick a service first." · "Enter what it costs."
    add-receipt    "Pick a store first." · "Enter how much you spent."
    add-card       "Give the card a name so you can tell it apart."
    add-account    "Enter the bank name."
    add-group      "Give the group a name so you can tell it from the others."
    salary         "Give each source a name and an amount." ·
                   "Pick the last payday for each source, so Skip can work out the next ones."

If a `handleSave` check fires for a field that lives on an **earlier** step, the flow **jumps back to
that step** and shows the message there. A person must never be told about a field they cannot see.

### 5.3 Save error

The mutation's own message, on the last step, above the primary button, `text-danger`, 13px, centred
— which is what `add-bill` does today. The button returns to its normal label and stays enabled, so
the retry is the button itself. No second "Retry" control. `warn()` fires once. Nothing is cleared.

### 5.4 Success

`success()` haptic, then the screen's existing navigation, unchanged: `router.back()` for the add
forms, `router.replace('/split-group?id=…')` for add-group. No confirmation screen, no toast, no
"Saved!" — the list you land on already shows the thing you just made, and that is the confirmation.

## 6. Per-flow table

| Flow | Shape | Step 1 Amount | Step 2 Details | Step 3 When | Amount required? |
|---|---|---|---|---|---|
| `add-expense.tsx` | **3 steps** | How much did you spend? | what for, paid by, split mode, who, exact shares | spent-on date | Yes (`total > 0`) |
| `add-bill.tsx` | **category chooser + 3 steps** | How much is the bill? | company, name, icon, category, paid with, note, schedule card | start/first-due date, repeat, end date, reminder | Yes |
| `add-subscription.tsx` | **3 steps** | How much does it cost? | service, paid with, note, active | renewal date, cycle, reminder | Yes |
| `add-receipt.tsx` | **3 steps** (+ Scan/Upload pills on step 1) | How much did you spend? | store, paid with, note | receipt date | Yes |
| `add-card.tsx` | **3 steps** | What is on the card today? | preview, network, name, colour, last 4 | due date, reminder | **No** — 0 is valid today |
| `add-account.tsx` | **3 steps** | What is in the account today? | bank, type, nickname, colour, last 4, expected income, pay frequency | last pay day, reminder | **No** — 0 is valid today |
| `add-group.tsx` | **2 steps** | — | name, icon, carried names | simplify-debts switch + the explainer | n/a |
| `add-member.tsx` | **single screen** | — | — | — | n/a |
| `salary.tsx` | **single screen**, restyled pickers | per source, via `AmountPad` | — | — | Yes, per source (unchanged) |
| `save-loan.tsx` | **single screen**, restyled | — | — | — | n/a — every figure is computed |
| `loan-calculator.tsx` | **single screen**, restyled `AmountPad` (incl. the `percent` variant) | — | — | — | n/a |

**The `add-bill` category chooser** stays a screen of its own, before the dots, titled
`What is this bill for?` with the existing `CategoryPicker`. Reason: it is what pre-fills the bill's
name, so it has to run before the details exist, and folding it into the dots would make bills a
four-dot flow while everything else is three. Back from step 1 returns to it. Editing skips it, as it
does today.

**`add-member.tsx` is the one place I am not following the brief, and here is why.** It is not a
form, it is three different ways to do the same thing — share a link, tap a friend already on Skip,
type a name. Each completes on its own; there is no "step 2" after tapping a friend, because the
friend is already added. Stepping it would bury the share link, which is the answer for the empty
list that opens this screen most of the time. It gets the pills sweep (share button, "Add a friend by
code" → pill, the friend rows' check circles) and nothing else. Founder's call — open question 1.

**Nothing is dropped.** Every `useState` on every one of these screens has a home in the table above:
I walked them field by field. The two I want a second pair of eyes on are `add-account`'s
`income` / `payFrequency` / `lastPayday` trio (they create a salary source as a side effect of saving
an account) and `add-bill`'s `reminderDraft` / `timeDraft` pair — both keep their exact current

## 7. Dark mode

The screenshot's tone, in our tokens. No new colour, no hex literal.

| Surface | Token |
|---|---|
| Page | `bg-surface` |
| Keypad tile, pill chip (unselected), pill select field | `bg-ink/5`, pressed `bg-ink/10` |
| Selected chip, selected day, primary button | `bg-control`, type `text-on-control` |
| Step pill (current) | `bg-ink` |
| Step dot (other) | `bg-ink/20` |
| Disabled primary | `bg-control` at `opacity-50` — the existing `Button` disabled treatment, which reads as the screenshot's muted grey pill on both grounds |

**No borders anywhere in these flows.** Not on tiles, not on chips, not on the pill select fields.
This is a deliberate departure from the direction doc's "borders instead of shadows": that rule
exists so cards separate in dark mode, and here separation comes from the tonal fill itself. Cards
elsewhere in the app keep their borders.

Check on **apricot and butter in light, plum and slate in dark** — the four accents where
`onControl` flips. `bg-ink/5` on `#1B181F` is subtle by design; verify the tile edge is visible at
minimum screen brightness before signing off.

## 8. Accessibility

- **Every key** labelled: `"1"` … `"9"`, `"0"`, `"Decimal point"`, `"Delete last digit"`. 64pt tall,
  so the 44pt floor is met with room.
- **The figure** is one `accessibilityLabel` on its container, read as money:
  `"Amount, 12 dollars 50"` — not `"$ 1 2 . 5 0"`. Use the same `formatCurrency`-shaped phrasing the
  `AmountTile` labels already use. `accessibilityLiveRegion="polite"` so a screen-reader user hears
  the running total, not just the last key.
- **Step announcement**: the indicator is a `progressbar` labelled `"Step 2 of 3"` (§1.2). On every
  step change, move focus to the step's question line via `AccessibilityInfo.setAccessibilityFocus`
  on its ref, so VoiceOver reads "How much did you spend?" rather than leaving focus on a Continue
  button that just moved.
- **Dynamic type caps**: question 1.3 · field labels 1.3 · body/help 1.4 · button 1.5 · figure and
  keypad digits `allowFontScaling={false}` (a 64px figure at 200% cannot fit any phone, and a keypad
  that reflows is a keypad you mis-hit). Everything else scales.
- **44pt minimum** on every target: keys 64, chips 40 + `hitSlop={4}` vertical, calendar cells 44,
  chevrons 44, back 44, primary 64.
- **Contrast**: check with `contrast()` from `src/lib/tone.ts`, not by eye. Floor 4.5:1 for type,
  3:1 for the tile edge and the today ring. The empty-state `text-muted` figure is decorative-ish but
  still type — it must clear 4.5:1, and if it does not on any accent, use `text-ink/40` rather than
  inventing a token.
- `accessibilityState={{ selected }}` on every chip, day and toggle half; `{{ disabled }}` on every
  disabled control.
